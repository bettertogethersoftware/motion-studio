# Motion Studio — MCP Setup and Tool Reference

Motion Studio's agent interface is a local MCP server speaking stdio: `engine/src/mcp/server.js`. It exposes a fixed set of tools for workspace/film/scene management, composition authoring, asset ingestion, previewing, and rendering — the same render engine and the same on-disk films and scenes the Studio web UI uses. It has no network listener and no shell or arbitrary-file tools; every file operation is sandboxed to the target scene's (or film's) own folder.

## The storage model (v0.20)

The flat "projects" model is gone. Storage is now **workspace → film → scene**:

- Each MCP server is bound to **one workspace** (`MOTION_STUDIO_WORKSPACE`, default `"default"`) — give each AI client its own so their work doesn't mingle. The Studio web UI shows every workspace at once; a given MCP server only ever sees its own.
- A **film** (id: `"<film>"`) is a real folder that owns its ordered scenes, a master audio timeline, caption/overlay tracks, its own `assets/` (master audio + overlays) and its own `out/` (the built deliverable). There is no standalone project concept — even a one-shot video is a film with a single scene.
- A **scene** (id: `"<film>/<scene>"`) is exactly what a "project" used to be — one composition, with the same folder contents including `scene.json` — living inside a film's `scenes/` folder. It's the unit that renders.
- A per-workspace **library** holds shared assets the human drops in directly (large media that would blow past the 25 MB tool-upload cap). Agents list it with `list_shared_assets` and pull files into a scene or film with `use_shared_asset`.

On disk: `<dataDir>/workspaces/<ws>/{workspace.json, library/, films/<film>/{film.json, assets/, out/, scenes/<scene>/}}` — `<dataDir>` being wherever the Studio's ⚙ **storage** settings point (default `<app>/data`).

## Connecting a client

For Claude Desktop, add to your config file (`%APPDATA%\Claude\claude_desktop_config.json` on Windows, `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS; create it if needed) and restart Claude Desktop:

```json
{
  "mcpServers": {
    "motionStudio": {
      "command": "node",
      "args": ["/absolute/path/to/motion-studio/engine/src/mcp/server.js"],
      "env": { "MOTION_STUDIO_WORKSPACE": "claude-desktop" }
    }
  }
}
```

For Claude Code: `claude mcp add motionStudio -e MOTION_STUDIO_WORKSPACE=claude-code -- node /absolute/path/to/engine/src/mcp/server.js`. Any MCP-capable client works the same way — point it at `node <path>/server.js` over stdio, with `MOTION_STUDIO_WORKSPACE` set in its env block.

`MOTION_STUDIO_WORKSPACE` names this agent's workspace (default `"default"`; created on first use — no setup step needed). Give every client a distinct workspace name: films and scenes created under one workspace are invisible to another workspace's tool calls (each server only lists/reads/writes inside its own), even though a human using the Studio UI sees all workspaces side by side. Two Claude Desktop profiles, a Claude Code session, and a CI agent should each get their own name.

Requirements are the same as the Studio's: Node ≥ 18 and FFmpeg ≥ 5 on PATH, and `npm install` completed in the engine folder (`npm run doctor` verifies). If prerequisites are missing, every tool responds with a structured `prereqs_missing` error naming what's absent — including `ffmpeg.effectivePath` and `ffmpeg.source`, so you can see *which* binary was probed and where that path came from.

The server shares the Studio's global settings (`<dataDir>/settings.json`, the ⚙ settings page): a `create_film` call that omits fps/width/height/durationInFrames gets the user's new-project defaults as the film's `sceneDefaults` (inherited by every scene created inside, unless a scene overrides them), `create_scene` additionally seeds each new scene's encode settings (crf/preset) from the user's global encode defaults, and a `render` that omits `workers` gets their default worker count (the response reports the value used). An explicit argument always wins. Creation defaults never rewrite a scene already on disk; worker and delivery-review settings are runtime defaults for the next render.

Delivery review is global too: `settings.json.render.review` names finding
codes to `block` or `warn` after the staged encoded file is inspected. A film's
optional `review` document field overrides either list for that film. The
default blocks only `frame_count_mismatch`; picture findings remain warnings so
intentional title cards, fades, and static holds still ship. Every successful
single-file delivery gains `<base>.review.json` and `<base>.contact.png` in its
`out/` folder, and a policy block returns `promotion_blocked` while preserving
the previous delivery and the staged evidence.

FFmpeg is resolved as `MOTION_STUDIO_FFMPEG` → the Studio's `settings.json` `ffmpeg.path` → `ffmpeg` on PATH, and the binary that passes the check is the one that runs your renders. Worth knowing because MCP clients launch the server themselves and often hand it a narrower PATH than your shell: if the Studio UI renders happily and every agent call returns `prereqs_missing`, that mismatch is the reason — set `MOTION_STUDIO_FFMPEG` in the server config's `env` block.

`MOTION_STUDIO_AGENT` (v0.23) names this director's identity — stamped on the revisions it renders, the deliveries it builds, its advice events, and its activity heartbeats, so the human's evidence views name their author. It defaults to the workspace name; set it explicitly when two agents share one workspace.

Other optional environment variables, settable in the server config's `env` block: `MOTION_STUDIO_HOME` relocates the data directory for this server (default: whatever the Studio's ⚙ **storage** settings say — since v0.22 the `data` folder beside the app unless changed, and an install from before v0.22 keeps its existing `~/.motion-studio`), `MOTION_STUDIO_WORKSPACES` and `MOTION_STUDIO_SETTINGS` do the same for the workspace tree and the settings file (each overrides the saved setting for this process only, and the Studio shows such a field locked — set one only to make this agent work somewhere else, because leaving all three unset is what keeps this server and the Studio sharing data, including after the user moves it), `MOTION_STUDIO_VENDOR_DIR` relocates the vendor-asset root the bundled defaults resolve from — the speech/MIDI exes, FluidSynth, SoundFonts, Piper voices, Whisper models and the 3D libs (default: the `vendor` folder beside the app; since v0.25 also configurable in the Studio's ⚙ storage settings, and the per-item hooks below always win over it), `MOTION_STUDIO_MAX_RENDERS` caps the number of renders a single server session will start (unset = unlimited) as a safety valve for unattended agent loops, `MOTION_STUDIO_FFMPEG` names the ffmpeg binary to use for the prerequisite check and for every render/film the server runs, and `MOTION_STUDIO_TTS_EXE` points at the Windows text-to-speech executable behind the `system` speech vendor (unset = the speech tools return `tts_unavailable`; everything else works). Speech has six vendors as of v0.20: `MOTION_STUDIO_TTS_VENDOR` (`system` | `azure` | `piper` | `elevenlabs` | `openai` | `deepgram`) selects one, the Piper vendor reads `MOTION_STUDIO_PIPER_EXE` / `MOTION_STUDIO_PIPER_VOICES`, and every cloud vendor reads its key **from the environment only** — never from `settings.json`: `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION`, `ELEVENLABS_API_KEY`, `OPENAI_API_KEY`, `DEEPGRAM_API_KEY` (or their `MOTION_STUDIO_*` forms). See the [text-to-speech guide](tts-setup.md). `MOTION_STUDIO_LIBS_DIR` overrides where the optional 3D library builds are vendored from (default `vendor/libs`, which is committed — `node scripts/fetch-libs.mjs` only upgrades/repairs it) — see [3D libraries](#3d-libraries-v07-optional). Music has two vendors as of v0.17: `MOTION_STUDIO_MUSIC_VENDOR` (`node` | `fluidsynth`) selects one, `node` being the default — it renders in-process on any OS and needs only `MOTION_STUDIO_SOUNDFONT` (a `.sf2`/`.sf3`, with a vendored default). The `fluidsynth` vendor additionally needs `MOTION_STUDIO_MIDI_EXE` and `MOTION_STUDIO_FLUIDSYNTH`; whatever is missing → `synthesize_music` returns `music_unavailable` naming it. See the [music guide](music-setup.md).

## Migrating from pre-v0.20

The first time this server starts against an existing data directory, it migrates a pre-v0.20 flat-project layout automatically — there is nothing to run by hand. Every saved film becomes a film folder (its scene projects move into `scenes/<slug>`, and its old "output project" — the `<name> — Master` convention — folds its `assets/`/`out/` into the film folder itself, then stops existing as a project); every project that wasn't part of a saved film becomes a single-scene film of the same name, so nothing silently disappears. Everything lands in the `default` workspace, since the old layout had no notion of which agent made what. The old `projects.json`/`films.json` registries, and any leftover output-project folder contents, move to `<dataDir>/legacy-v019/` together with a `migration-report.json` mapping every old project/film id to its new one — **nothing is deleted**. Migration is one-shot (it re-runs only if it didn't finish last time) and a hard failure raises `migration_failed` while leaving the legacy files untouched for a retry. A data directory that's already on the new layout, or has never been used, skips this entirely.

## Tools

All tools return JSON text content; failures set `isError` with a body of `{ code, message, detail? }` using the stable codes listed in [architecture.md](architecture.md) §6. The v0.20 storage restructure retired `project_not_found` / `project_already_exists` and added `scene_not_found`, `scene_already_exists`, `workspace_not_found`, `film_already_exists`, `invalid_id` and `migration_failed`.

Every `film` / `scene` / `target` argument is a **workspace-local id**: a bare slug (`"my-film"`) for a film, `"<film>/<scene>"` for a scene, and either shape for a `target` (scene or film). The shape is validated before anything is looked up — a malformed id fails fast with `invalid_id`; a well-formed one that doesn't exist fails with `film_not_found` or `scene_not_found`. Paths passed to file tools are always **scene-relative** (film-relative for asset tools targeting a film); absolute paths and `..` escapes are rejected with `path_not_allowed`.

#### `plan.signature` — the film's encode contract (v0.22)

Every film tool that returns a `plan` (`get_film`, `list_films { detail: "full" }`,
`update_film`, `build_film { plan: true }`) carries it, because they share one
projection (`get_film`'s compact `scenes`/`summary` details also carry it —
the signature is the one thing only the engine knows).

```jsonc
"signature": {
  "id": "1920x1080@30/mp4/opaque/yuv420p",     // the key validateScenes enforces
  "width": 1920, "height": 1080, "fps": 30,
  "format": "mp4", "container": "mp4",          // prores → container "mov"
  "pixFmt": "yuv420p", "transparent": false,
  "video": { "codec": "libx264", "crf": 18, "preset": "medium" },
  "audio": { "codec": "aac", "bitrate": "192k" },
  "ffmpegArgs": ["-c:v","libx264","-preset","medium","-crf","18",
                 "-pix_fmt","yuv420p","-movflags","+faststart"],
  "copyConcat": true,
  "color": { "stated": false, "primaries": null,      // the engine states no
             "transfer": null, "matrix": null,        // colour; see below
             "range": null },
  "mustMatch":     ["codec","width","height","fps","pixFmt","container"],
  "neednotMatch":  ["gopSize","profile","level","bitrate"],
  "matchForLooks": ["crf","preset","colorPrimaries","colorTransfer",
                    "colorMatrix","colorRange"],
  "warnings": []
}
```

Motion Studio's long-form guarantee is that scenes share an encode signature and
therefore concatenate losslessly. The engine has always computed and enforced
that; this is it **stated**, so a file arriving from outside can be made to match
without guessing or without rendering something first and probing it.

- **`ffmpegArgs` is the answer, verbatim.** It is literally the argument list the
  engine's own encoder uses — pass it through rather than rebuilding it from the
  fields, which is where the guesswork creeps in.
- **`neednotMatch` matters as much as `mustMatch`.** Each segment is its own
  encode and opens on a keyframe, which is all `concat -c copy` requires, so
  pinning GOP/profile/level/bitrate is wasted effort. **Measured:** a segment
  encoded at a deliberately different profile *and* GOP concatenates and decodes
  back bit-identically.
- **`video.codec` is the ffmpeg encoder id** (`libx264`), while `probe_asset`
  reports the codec *name* (`h264`). Comparing them directly is a guaranteed
  false mismatch.
- **`matchForLooks` is the third answer**, for parameters that do not affect the
  join at all but where the joined file keeps only segment 1's — a mismatch is a
  look difference, not an error. `crf`/`preset` are there (not required for the
  concat, but footage ignoring them looks different from the scenes beside it;
  using `ffmpegArgs` verbatim gets them right for free, and a `warnings` entry
  appears when the film's own scenes disagree on them), and so are the colour tags.
- **`color` is a stated output contract.** Final colour-carrying outputs report
  BT.709 primaries/matrix, sRGB transfer, and TV range; `matchFilm` performs a
  real conversion to that profile in its existing filter chain. If source tags
  are incomplete, the response's `assumptions.color` says it was treated as
  BT.709. GIF and PNG-sequence remain honestly unstated. See
  [film-setup.md](film-setup.md#the-consistency-invariant) for the invariant.
- **`signature: null`** means the film has no resolvable scenes yet, so nothing is
  enforced — deliberately not a guess from `sceneDefaults`.
- **Check `copyConcat`** first: a `gif` or `png-sequence` film cannot be
  stream-copied, and `warnings` says so.

The output filename's extension follows the format automatically. `output.audioLimiter` (default `true`) brick-walls the mixed audio at −1 dBFS; set `false` only if you want the summed mix passed through untouched (track gains then sum directly — `amix` runs with `normalize=0`). ### Composition files and assets

Composition source files are always scene-scoped (`scene`, `"<film>/<scene>"`). Binary assets take a `target`, which is either a scene (composition-local assets) or a bare film id (master audio / overlay files that live in the film's own `assets/` and attach to its master timeline).

| tool | arguments | returns / notes |
|---|---|---|
| `read_composition_file` | `scene`, `path` | `{ path, content }`. Errors: `scene_not_found`, `file_not_found`, `path_not_allowed`, `invalid_id`. |
| `write_composition_file` | `scene`, `path`, `content` | Atomic write (temp + rename) into the scene folder. `.js`/`.mjs` content is syntax-checked first and rejected with `syntax_error` (line/column in `detail`) **before touching disk** — the previous file version survives a rejected write; `.json` is likewise parsed and rejected on bad JSON. Allowed extensions: `.html .htm .css .js .mjs .json .svg .txt .md`; `scene.json` is deny-listed (use `update_scene_config`). **Determinism lint:** JS/CSS is scanned for frame-driven contract violations and any hits come back as `warnings: [{ rule, line, snippet, message }]` on the write response `{ path, bytes, warnings? }` — these are **advisory, the file is written regardless**, but treat them as real unless the usage is known-safe. Comments and string literals are excluded from the scan. Rules: `date-now`, `performance-now`, `new-date`, `set-timeout`, `set-interval`, `request-animation-frame`, `math-random`, `three-clock`, `babylon-render-loop`, `babylon-begin-animation`, `css-transition`, `css-animation`, `canvas-save-restore` (a named function calling `ctx.save()` more often than `ctx.restore()` — the leftover transform/clip/style silently moves or hides everything drawn later in the frame), `classlist-mutation` (`classList.add`/`remove` accumulates DOM state across frames — hide scene containers by default in CSS; `classList.toggle(name, bool)` is exempt) and `sequence-gap` (literal `Sequence(start, duration)` calls statically checked against the scene duration: coverage holes and uncovered tails are named with frame ranges; dynamic args, single sequences, and calls spanning mutually exclusive helper scopes are left alone). Errors: `scene_not_found`, `syntax_error`, `path_not_allowed`, `invalid_id`. |
| `sync_shared_files` | `sourceScene`, `targetScenes` (array, min 1), `files` (array of scene-relative paths, min 1) | Copies the named files from `sourceScene` into every scene in `targetScenes`, overwriting them. The maintenance half of the recommended multi-scene film pattern (every scene ships the SAME `composition.js` and differs only in a small `scene.js`) — each scene owns its own copy, so without this a one-line engine fix means rewriting it once per scene. Each target gets the same syntax check + determinism lint as `write_composition_file` (warnings come back per target), and **all** source files are read before anything is written, so a bad path fails before it half-updates the film. The source is skipped if it appears in `targetScenes`; `scene.json` remains deny-listed. Does **not** invalidate rendered output — re-render the affected scenes. Returns `{ sourceScene, files, scenesUpdated, results: [{ scene, written }] }`. Errors: `scene_not_found`, `invalid_config` (empty list), `syntax_error`, `invalid_id`. |

### Audio / narration (v0.6; six vendors since v0.20)

Narration comes from a **speech vendor**: `system` (the Windows speech exe at `MOTION_STUDIO_TTS_EXE`), `azure` (Azure AI Speech, needing `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION` in the environment), `piper` (local neural voices — needs Piper installed via `pip install piper-tts` plus downloaded `.onnx` voices; offline, free, any OS), `elevenlabs` (ElevenLabs cloud voices — best quality; needs `ELEVENLABS_API_KEY`; free tier with attribution), `openai` (OpenAI `gpt-4o-mini-tts` — style-instructable; needs `OPENAI_API_KEY`; no free tier), or `deepgram` (Deepgram Aura-2 — best free cloud tier, $200 signup credit; needs `DEEPGRAM_API_KEY`). The user may configure an ordered **preference chain** rather than one vendor, in which case a vendor-less call uses the highest-ranked one that is available and the result carries `vendorChain` + a `vendorNote` naming anything skipped; **a vendor you name explicitly is never redirected** — it runs or it fails. Synthesized narration is a normal audio track — mixed into the final render/build by FFmpeg (mp4/webm/prores carry audio; gif/png-sequence do not). `capture_preview_frame` is always silent.

Attach a heavier rendering library to a scene. The build is copied **locally**
into the scene (never a CDN at render time, so renders stay hermetic). Builds

### Music (v0.8; two vendors since v0.17)

rendered against a General MIDI SoundFont, and — like `synthesize_speech` — the

`node` (default — renders in-process, works on any OS, needs only a SoundFont)

configured default — `list_vendors` says which that is. A vendor that is not
usable → `music_unavailable`, naming what to fix (and any sibling that is ready).
See [music-setup.md](music-setup.md).

| `build_film` | `film` (req), `plan?` (bool), `outputFilename?` (master override + persist), `deliverable?` (saved platform version id), `audioTargetPeakDb?` (override + persist, −60..0 or `null`), `burnCaptions?` (override + persist) | Assembles the film's already-rendered scenes into its deliverable, as an **ASYNC JOB** — returns a `jobId` immediately; block with `wait_for_render` (or poll `get_render_status`). The master concatenates scene outputs **losslessly** (`ffmpeg -c copy`, no re-encode, near-instant), lays the film's master audio timeline over the whole length (replacing per-scene audio when present), and — only when the film has overlays or burns captions — runs ONE finishing encode that composites them. Pass a saved `deliverable` such as `shorts-9x16` for Stage A: the same master cut is re-encoded at that version's target geometry/crop/caption style, with its own output filename, `.srt`, review JSON and safe-guide contact sheet. Variant results carry `deliverable` and `reEncoded: true`; do not combine `deliverable` with `outputFilename`. Captions always also write a `.srt` sidecar. Output lands in the film's `out/`. Every scene must already be rendered (`scene_not_rendered` lists offenders) **and still match the settings it was rendered at** (`stale_render` — colour changes now count alongside duration/size/fps/format); scenes must share resolution/fps/format (`inconsistent_scenes` — only mp4/webm/prores concatenate losslessly). The finished job carries measured `audio`, advisory `picture: { staticFrames, blackFrames, cutsChecked, cutsSuspect }`, and `review: { reviewPath, contactPath, warnings }`. The JSON/contact pair was made from the staging file before promotion; its policy may return `promotion_blocked`, preserving the prior movie. Read it before calling a build done. Set `audioTargetPeakDb` (e.g. `-2`) to have the film measured and re-muxed once to that level instead of guessing gains. Pass `plan: true` to get `{ film, plan: true, totalFrames, durationSeconds, fps, format, sceneLayout, problems }` WITHOUT building (each `sceneLayout` entry carries `rendered` plus **`renderVerified`** — `true` matches the config, `false` means stale with a `staleRender` breakdown, `null` means rendered before the sidecar existed) — works before the scenes are rendered, which is exactly when you need each `filmOffset` to place narration and cues; nothing is assembled or written. Iterating? Re-render only the scene you changed, then `build_film` again — other scenes' outputs are reused. Non-plan calls return `{ jobId, state, queuePosition?, outputPath, totalFrames, filmId, deliverable, hint }`. Errors: `unknown_deliverable`, `scene_not_rendered`, `stale_render`, `inconsistent_scenes`, `promotion_blocked`, `invalid_film`, `file_not_found` (missing master-audio/overlay asset), `path_not_allowed`, `film_not_found`, `invalid_id`, `prereqs_missing`. |

Note there is **no separate "saved film" concept anymore** — the film document `build_film` reads is the same one `create_film`/`update_film`/`get_film` edit, and the same one the Studio's film editor shows. The concat step is always `-c copy` (lossless): the scenes' own `output.crf`/format is what ships, so choose the deliverable quality when you render each scene. A finishing re-encode happens exactly once, and only when the film has overlays or burns captions.

| `measure_render` | `target`, `path?` (target-relative; must begin `out/` or `assets/`, e.g. `out/output.mp4`), `waitMs?` = 45000 | Runs a full low-resolution pass over the encoded picture and returns `{ motionEnvelope, staticRuns, blackRuns, solidFrames, cutCheck, warnings }`. `path` defaults to the target's canonical output; a bare filename is rejected. ### Rendering

Schema compatibility: `render.frameRange` is published as a homogeneous integer
array with `minItems: 2` and `maxItems: 2`. The call shape remains
`[startFrame, endFrame]`, while strict MCP importers avoid the draft-07 tuple
form that can cause them to drop the entire `render` tool.

| tool | arguments | returns / notes |
|---|---|---|
| `render` | `scene`, `frameRange?` = `[start, end]` inclusive, `workers?` (default: the user's global **default workers** setting; omit unless you have a reason), `outputFilename?`, `preflight?` = true, `proxy?` = `{ scale?, frameStep? }` | Starts an async job for the scene's configured output format; returns `{ jobId, state, queuePosition?, outputPath, totalFrames, workers, proxy? }` immediately. One render runs at a time; further submissions **queue FIFO**, up to 10 deep, and start automatically. A full queue fails with `queue_full`. `workers` > 1 splits capture across parallel Chromium processes. **Pre-flight:** evenly-spaced frames (both endpoints included) are probed before the render commits, so a composition that only breaks at frame 90 fails in seconds instead of after 90 frames and N spawned workers. Failures keep their real code (`composition_error` / `frame_timeout`) with `detail.phase = "preflight"`. Skipped under 30 frames; pass `preflight: false` to disable. **Delivery review:** when the encode finishes, its staged file is frame-count checked, picture-measured, and sampled into `<base>.review.json` plus `<base>.contact.png` before promotion. The default policy blocks a measured count mismatch with `promotion_blocked` (preserving the prior delivery); `framesVerified` is false only when ffprobe is unavailable, which is recorded as an explicit review finding. The terminal status carries `review: { reviewPath, contactPath, warnings }`. **Render lock:** the scene is locked for the duration, so a *second process* rendering the same scene fails fast with `render_already_in_progress` instead of silently interleaving frame writes. In-process submissions still queue as before. **Proxy/motion preview:** `proxy: { scale?, frameStep? }` renders a cheap draft for checking motion in ~1/8 the time — capture at `width×scale` (0.1–1, default 0.5; dims floored to even for the encoders), every `frameStep`-th frame (default 2), encoded at the rational rate `fps/frameStep` so wall-clock duration is preserved. Serial only (`workers` is ignored), pre-flight and the audio mux are skipped, and the output gets `.proxy` before the extension (`output.proxy.mp4`) so a draft can never overwrite the deliverable. Bad values fail with `invalid_config` naming the offending field. Do NOT set mp4 `crf` to 0 for "maximum quality": CRF 0 is lossless H.264 (Hi444PP profile), which most players show as BLACK video with working audio — `crf 18` is the visually-lossless choice that plays everywhere; such a render still succeeds but carries `encodingWarnings` in the job status. |
| `get_render_status` | `jobId` | `{ state: queued\|running\|done\|error\|cancelled, framesDone, totalFrames, percent, renderFps, etaMs, queuePosition?, outputPath?, error? }`. Poll until terminal — or use `wait_for_render` instead of a polling loop. Scene renders add `staticFrames`; film builds add advisory `picture: { staticFrames, blackFrames, cutsChecked, cutsSuspect }`; audio builds carry measured `audio`. Successful single-file deliveries add `review: { reviewPath, contactPath, warnings }`, with each warning already classified `block`/`warn`/`info`; `reviewArtifactWarning` means the movie promoted but a derived review file could not. `encodingWarnings` lists player-compatibility advisories. Proxy jobs carry `proxy: { scale, frameStep }`. **Non-render jobs share this surface**: `kind` says which — e.g. `"transcribe"`, `"audio-preview"`, or `"render-review"` — they have no frames (`percent` stays 0, watch `phase`), and a finished one carries its whole answer in `result`. Error: `job_not_found`. |
| `wait_for_render` | `jobIds` = `[…]` (1–16), `timeoutMs?` = 30000 (1,000–50,000 ms) | Blocks until **every** listed job is terminal, or the timeout elapses. Returns `{ timedOut, jobs }`; each entry has the `get_render_status` shape and task results such as transcripts, audio-preview reports, or render measurements. Check states individually: one failed scene does not stop the others. Waiting on queued jobs is fine (FIFO). A timeout is **not** an error; call again to keep watching. Job ids live only in server memory: an unknown/expired id is returned as terminal `{ state: "not_found" }`, so it cannot hide the results for surviving ids in a batch. |
| `cancel_render` | `jobId` | Aborts a running job and kills every child process (Chromium workers, FFmpeg); dequeues a queued job without starting it. Idempotent on finished jobs. |
| `list_render_jobs` | — | All jobs this session, newest first, with status snapshots. Both lanes appear: renders/builds (`kind: "render"`, one at a time) and non-render jobs such as transcriptions, which run in their own lane and never wait behind a render. |
| `get_logs` | `jobId`, `tail?` = 100 | The job's log lines (engine phases, warnings, FFmpeg stderr on failure) — read this before diagnosing a failed render or build. |

### The production loop (v0.23): advice, revisions, deliveries, status

Motion Studio's working model is AI-directed, human-advised: the agent
produces the film unattended, and the human leaves durable advice on the
Studio's film page. There is **no approval gate** — the agent checks for
advice at its checkpoints (task start, after planning, before expensive
generation, after each scene revision, before `build_film`, before reporting
completion) and never waits or polls for a human response.

| tool | arguments | returns / notes |
|---|---|---|
| `get_capabilities` | — | One call that tells a director what it is working with: engine version, `workspace`/`agent` identity, the scene/footage/sequence model, formats, configured vendor names (no probing, no secrets), production-loop features and checkpoints, limits, and — v0.26 — a `tiers` block (core / free-local / pack / byok per capability, existence-checked, with the exact per-OS fix command when something is not ready; key *presence* only for cloud vendors, never values) plus a `packs` block (every fetchable pack from the Slice B manifest with its `installed` state and the `npm run fetch-pack -- <id>` command; a structured `error` on a core-only install). |
| `check_human_advice` | `film?`, `limit?` | Unresolved advice, **oldest first**, across the workspace (or one film). Read-only: marks nothing, hides nothing — including items another agent acknowledged and abandoned (their lease expires). Each item carries the human's wording, the structural target (`film` / `sequence` / `scene` / `footage` / `audio` / `caption` / `overlay` + frames), and the exact `observation` (delivery/revision/frame they were watching). Empty result → continue immediately. |
| `acknowledge_human_advice` | `film`, `adviceId` | Records receipt — the human sees "AI received it". Idempotent; does not commit to applying it and does not hide it from other agents. |
| `begin_advice_work` | `film`, `adviceId`, `ttlSeconds?` = 900 | Renewable TTL work lease so two agents cannot process one item. `advice_lease_held` names the live holder and expiry; an expired lease is taken over silently (that is the crash recovery). |
| `resolve_human_advice` | `film`, `adviceId`, `outcome` (`applied` \| `partially-applied` \| `not-applied` \| `superseded` \| `needs-clarification`), `explanation` (the human reads it), `revisionIds?`, `deliveryId?`, `combinedAdviceIds?`, `requestId?` | Records the outcome and links the evidence. `needs-clarification` is NOT terminal — the explanation is your question and the human answers with linked follow-up advice. | `list_human_advice` | `film`, `status?`, `scene?`, `sequence?`, `itemId?` (a footage/audio/caption/overlay item id), `limit?` | Advice history at any scope, newest first (unresolved: oldest first) — read past direction before reworking an area the human has commented on. |

| `list_scene_revisions` | `scene` | Every archived revision, newest first: id, time, agent, frames, `note`, linked advice, `current` flag. | `use_scene_revision` | `scene`, `revisionId` | Repoints the scene's live output at an archived take (staged + atomic rename, sidecar re-stamped) — the normal answer to prefer-revision advice. | `wait_render_group` | `groupId`, `timeoutMs?` = 30000 (max 50000), `since?` | Waits on a group (v0.26, TE P0-7). This is the production loop's read — poll it with `since` instead of re-reading `get_film` per scene. |

## Typical agent session

The recommended shape for anything longer than a single shot: one film, one scene per beat, master audio placed on the film rather than per scene.

```
create_film { name: "Product Launch", fps: 30, width: 1920, height: 1080 }
                                                 → { film: "product-launch", sceneDefaults: {...}, next: … }

create_scene { film: "product-launch", name: "Intro", durationInFrames: 150 }
                                                 → { scene: "product-launch/intro", config, files }
create_scene { film: "product-launch", name: "Feature Tour", durationInFrames: 240 }
                                                 → { scene: "product-launch/feature-tour", … }
create_scene { film: "product-launch", name: "Outro", durationInFrames: 120 }
                                                 → { scene: "product-launch/outro", … }

(read resource motion-studio://reference/frame-api)
write_composition_file { scene: "product-launch/intro", path: "composition.js", content: … }
                                                 → syntax_error → fix → ok; warnings? fix determinism hits
capture_preview_frames { scene: "product-launch/intro", count: 5 }
                                                 → inspect 5 images from ONE page load
(… author + preview feature-tour and outro the same way …)

render { scene: "product-launch/intro" }        → jobId1
render { scene: "product-launch/feature-tour" } → jobId2 (queues behind jobId1)
render { scene: "product-launch/outro" }        → jobId3 (queues)
wait_for_render { jobIds: [jobId1, jobId2, jobId3] }
                                                 → blocks → all done

build_film { film: "product-launch", plan: true }
                                                 → sceneLayout: each scene's filmOffset — read this BEFORE
                                                   placing narration, so cues land exactly on the cut

synthesize_speech { target: "product-launch", text: "…", sentenceTimings: true }
                                                 → narration attached to the film's master timeline at frame 0
synthesize_music { target: "product-launch",
                    spec: { bpm: 96, progression: ["D","A","Bm","G"], style: "pad-ballad" },
                    gainDb: -10, duck: true }
                                                 → theme tiled across the film, ducked under narration
preview_audio { target: "product-launch" }      → audition the whole soundtrack; check balanceWarnings

build_film { film: "product-launch", audioTargetPeakDb: -2 }
                                                 → jobId4 (async)
wait_for_render { jobIds: [jobId4] }            → done, outputPath,
                                                   audio: { peakDb, clipping, balanceWarnings }
```

For a one-shot video, the same tools collapse to a single scene: `create_film` → one `create_scene` → author/preview/render that scene → `build_film` (no master audio needed unless you want narration/music, in which case `synthesize_*` still targets the film).

To deliver a transparent overlay instead of an mp4:
`update_scene_config { scene: "<film>/<scene>", patch: { output: { format: "webm", transparent: true } } }`,
give the composition a transparent background, and render — the output drops
onto any timeline as an alpha overlay.

The updated agent skill in [SKILL.md](SKILL.md) encodes this workflow, the authoring contract, and error handling for direct use as a Claude skill (pair it with `frame-api.md` as `references/frame-api.md`).
