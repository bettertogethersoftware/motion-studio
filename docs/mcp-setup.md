# Motion Studio — MCP Setup and Tool Reference

Motion Studio's agent interface is a local MCP server speaking stdio: `engine/src/mcp/server.js`. It exposes a fixed set of tools for workspace/film/scene management, composition authoring, asset ingestion, previewing, and rendering — the same render engine and the same on-disk films and scenes the Studio web UI uses. It has no network listener and no shell or arbitrary-file tools; every file operation is sandboxed to the target scene's (or film's) own folder.

## The storage model (v0.20)

The flat "projects" model is gone. Storage is now **workspace → film → scene**:

- Each MCP server is bound to **one workspace** (`MOTION_STUDIO_WORKSPACE`, default `"default"`) — give each AI client its own so their work doesn't mingle. The Studio web UI shows every workspace at once; a given MCP server only ever sees its own.
- A **film** (id: `"<film>"`) is a real folder that owns its ordered scenes, a master audio timeline, caption/overlay tracks, its own `assets/` (master audio + overlays) and its own `out/` (the built deliverable). There is no standalone project concept — even a one-shot video is a film with a single scene.
- A **scene** (id: `"<film>/<scene>"`) is exactly what a "project" used to be — one composition, with the same folder contents including `scene.json` — living inside a film's `scenes/` folder. It's the unit that renders.
- A per-workspace **library** holds shared assets the human drops in directly (large media that would blow past the 25 MB tool-upload cap). Agents list it with `list_shared_assets` and pull files into a scene or film with `use_shared_asset`.

On disk: `<dataDir>/workspaces/<ws>/{workspace.json, library/, films/<film>/{film.json, assets/, out/, scenes/<scene>/}}`.

## Connecting a client

For Claude Desktop, add to your config file (`%APPDATA%\Claude\claude_desktop_config.json` on Windows, `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS; create it if needed) and restart Claude Desktop:

```json
{
  "mcpServers": {
    "motionStudio": {
      "command": "node",
      "args": ["/absolute/path/to/motion-studio/engine/src/mcp/server.js"],
      "env": { "MOTION_STUDIO_WORKSPACE": "claude-desktop" }
    }
  }
}
```

For Claude Code: `claude mcp add motionStudio -e MOTION_STUDIO_WORKSPACE=claude-code -- node /absolute/path/to/engine/src/mcp/server.js`. Any MCP-capable client works the same way — point it at `node <path>/server.js` over stdio, with `MOTION_STUDIO_WORKSPACE` set in its env block.

`MOTION_STUDIO_WORKSPACE` names this agent's workspace (default `"default"`; created on first use — no setup step needed). Give every client a distinct workspace name: films and scenes created under one workspace are invisible to another workspace's tool calls (each server only lists/reads/writes inside its own), even though a human using the Studio UI sees all workspaces side by side. Two Claude Desktop profiles, a Claude Code session, and a CI agent should each get their own name.

Requirements are the same as the Studio's: Node ≥ 18 and FFmpeg ≥ 5 on PATH, and `npm install` completed in the engine folder (`npm run doctor` verifies). If prerequisites are missing, every tool responds with a structured `prereqs_missing` error naming what's absent — including `ffmpeg.effectivePath` and `ffmpeg.source`, so you can see *which* binary was probed and where that path came from.

The server shares the Studio's global settings (`~/.motion-studio/settings.json`, the ⚙ dialog): a `create_film` call that omits fps/width/height/durationInFrames gets the user's new-project defaults as the film's `sceneDefaults` (inherited by every scene created inside, unless a scene overrides them), `create_scene` additionally seeds each new scene's encode settings (crf/preset) from the user's global encode defaults, and a `render` that omits `workers` gets their default worker count (the response reports the value used). An explicit argument always wins, and settings apply only at creation time — nothing on disk is rewritten because a global changed later.

FFmpeg is resolved as `MOTION_STUDIO_FFMPEG` → the Studio's `settings.json` `ffmpeg.path` → `ffmpeg` on PATH, and the binary that passes the check is the one that runs your renders. Worth knowing because MCP clients launch the server themselves and often hand it a narrower PATH than your shell: if the Studio UI renders happily and every agent call returns `prereqs_missing`, that mismatch is the reason — set `MOTION_STUDIO_FFMPEG` in the server config's `env` block.

Other optional environment variables, settable in the server config's `env` block: `MOTION_STUDIO_HOME` relocates the data directory (workspaces + settings; default `~/.motion-studio`, and it must match what the Studio uses if you want the two to share data), `MOTION_STUDIO_MAX_RENDERS` caps the number of renders a single server session will start (unset = unlimited) as a safety valve for unattended agent loops, `MOTION_STUDIO_FFMPEG` names the ffmpeg binary to use for the prerequisite check and for every render/film the server runs, and `MOTION_STUDIO_TTS_EXE` points at the Windows text-to-speech executable behind the `system` speech vendor (unset = the speech tools return `tts_unavailable`; everything else works). Speech has six vendors as of v0.20: `MOTION_STUDIO_TTS_VENDOR` (`system` | `azure` | `piper` | `elevenlabs` | `openai` | `deepgram`) selects one, the Piper vendor reads `MOTION_STUDIO_PIPER_EXE` / `MOTION_STUDIO_PIPER_VOICES`, and every cloud vendor reads its key **from the environment only** — never from `settings.json`: `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION`, `ELEVENLABS_API_KEY`, `OPENAI_API_KEY`, `DEEPGRAM_API_KEY` (or their `MOTION_STUDIO_*` forms). See the [text-to-speech guide](tts-setup.md). `MOTION_STUDIO_LIBS_DIR` overrides where the optional 3D library builds are vendored from (default `engine/vendor/libs`, which is committed — `node scripts/fetch-libs.mjs` only upgrades/repairs it) — see [3D libraries](#3d-libraries-v07-optional). Music has two vendors as of v0.17: `MOTION_STUDIO_MUSIC_VENDOR` (`node` | `fluidsynth`) selects one, `node` being the default — it renders in-process on any OS and needs only `MOTION_STUDIO_SOUNDFONT` (a `.sf2`/`.sf3`, with a vendored default). The `fluidsynth` vendor additionally needs `MOTION_STUDIO_MIDI_EXE` and `MOTION_STUDIO_FLUIDSYNTH`; whatever is missing → `synthesize_music` returns `music_unavailable` naming it. See the [music guide](music-setup.md).

## Migrating from pre-v0.20

The first time this server starts against an existing `~/.motion-studio` data directory, it migrates a pre-v0.20 flat-project layout automatically — there is nothing to run by hand. Every saved film becomes a film folder (its scene projects move into `scenes/<slug>`, and its old "output project" — the `<name> — Master` convention — folds its `assets/`/`out/` into the film folder itself, then stops existing as a project); every project that wasn't part of a saved film becomes a single-scene film of the same name, so nothing silently disappears. Everything lands in the `default` workspace, since the old layout had no notion of which agent made what. The old `projects.json`/`films.json` registries, and any leftover output-project folder contents, move to `<dataDir>/legacy-v019/` together with a `migration-report.json` mapping every old project/film id to its new one — **nothing is deleted**. Migration is one-shot (it re-runs only if it didn't finish last time) and a hard failure raises `migration_failed` while leaving the legacy files untouched for a retry. A data directory that's already on the new layout, or has never been used, skips this entirely.

## Tools

All tools return JSON text content; failures set `isError` with a body of `{ code, message, detail? }` using the stable codes listed in [architecture.md](architecture.md) §6. The v0.20 storage restructure retired `project_not_found` / `project_already_exists` and added `scene_not_found`, `scene_already_exists`, `workspace_not_found`, `film_already_exists`, `invalid_id` and `migration_failed`.

Every `film` / `scene` / `target` argument is a **workspace-local id**: a bare slug (`"my-film"`) for a film, `"<film>/<scene>"` for a scene, and either shape for a `target` (scene or film). The shape is validated before anything is looked up — a malformed id fails fast with `invalid_id`; a well-formed one that doesn't exist fails with `film_not_found` or `scene_not_found`. Paths passed to file tools are always **scene-relative** (film-relative for asset tools targeting a film); absolute paths and `..` escapes are rejected with `path_not_allowed`.

### Workspace

| tool | arguments | returns / notes |
|---|---|---|
| `get_workspace` | — | Describes the workspace this server is bound to (`MOTION_STUDIO_WORKSPACE`): `{ workspace, name, path, films: [{ film, name, scenes, broken? }], library: { files, bytes } }`. Every other tool operates inside this one workspace. Error: `prereqs_missing`. |

### Films

| tool | arguments | returns / notes |
|---|---|---|
| `list_films` | — | Every film in this workspace with its resolved plan: scene layout (each scene's `filmOffset` — what you place master audio and cues against), total length, and a `problems` list (unrendered scenes, signature mismatches, missing assets, out-of-range captions/overlays). A film with problems can be edited but not built. Returns `{ workspace, films: [{ film, name, updatedAt, totalFrames, durationSeconds, fps, format, sceneLayout, problems }] }`; a folder with a broken/missing `film.json` comes back as `{ film, name, broken: true }` instead of disappearing. |
| `create_film` | `name` (req), `slug?`, `fps?` (1..240), `width?` (2..7680, even), `height?` (2..4320, even), `durationInFrames?`, `outputFilename?` (default `"film"`) | Creates the film — the container a video is authored in. `fps`/`width`/`height`/`durationInFrames` become the film's `sceneDefaults`: every scene created inside inherits them unless overridden, which is what keeps scenes concat-compatible (scenes must share resolution/fps/format to stitch losslessly) without restating dimensions per scene. Omitted dimensions fall back to the user's global new-project defaults (factory: 30fps 1920×1080, 150 frames). Returns `{ film, name, path, sceneDefaults, outputFilename, next }`. Errors: `film_already_exists`, `invalid_film`, `invalid_id`, `prereqs_missing`. |
| `get_film` | `film` | The full film document (scene order, master audio, overlays, captions, `captionStyle`, mastering options) plus the resolved `plan`: per-scene `filmOffset`/duration/rendered state and a `problems` list. **Always read `filmOffset` from here** — never accumulate scene durations by hand. Also returns `editorUrl`, a link into the Studio's visual film editor. Errors: `film_not_found`, `invalid_id`. |
| `update_film` | `film`, plus any of: `name`, `scenes?` (`[{slug}]` — play order; reorder or drop scenes here, create with `create_scene`), `outputFilename?`, `sceneDefaults?` (`{fps?,width?,height?,durationInFrames?}`, inherited by newly created scenes), `audio?` (master timeline: `[{id?,label?,src,startInFrames?,gainDb?,trimEndInFrames?,fadeInFrames?,fadeOutFrames?,duck?}]`), `overlays?` (`[{id?,src,fromFrame,toFrame,xPct?,yPct?,widthPct?,opacity?}]` — image/video under the film's `assets/`; transparent `.webm` keeps alpha), `captions?` (`[{id?,text,fromFrame,toFrame}]`), `captionStyle?` (`{sizePct? 1..20 default 4.5, position? "bottom"\|"top"}`), `audioTargetPeakDb?` (−60..0 or `null`), `burnCaptions?` | Patches the film document. Omitted fields keep their saved values; **array fields REPLACE wholesale** (a timeline edit is a statement of the whole track). Audio/overlay `src` paths are relative to the FILM's `assets/` — put master audio there by targeting the film id in `synthesize_*` / `write_asset_file`. Times are frames on the film timeline; get scene offsets from `get_film`'s plan. Returns `{ film, name, updatedAt, plan }` — the plan's `problems` list means the film saved fine but cannot build yet. The Studio's film editor edits this same document; changes are shared both ways. Errors: `invalid_film` (full problem list in `detail`), `film_not_found`, `invalid_id`. |
| `remove_film` | `film`, `deleteFiles?` = false | `deleteFiles=false` removes only the film document — the folder with its scenes, assets and built output stays on disk (listed as `broken` by `list_films` until cleaned up). `deleteFiles=true` deletes the ENTIRE film folder, including every scene and rendered output. Irreversible — confirm with the user first. Returns `{ id, name, path, removed, filesDeleted }`. Errors: `film_not_found`, `invalid_id`. |

### Scenes

| tool | arguments | returns / notes |
|---|---|---|
| `create_scene` | `film` (req), `name` (req), `slug?`, `fps?`, `width?` (even), `height?` (even), `durationInFrames?` | Scaffolds a new scene from the default template inside `film` and appends it to the film's play order. `durationInFrames` = seconds × fps. Dimensions you omit inherit the film's `sceneDefaults` (set at `create_film`) — read `config` in the response to see what it actually got. Returns the scene id (`"<film>/<scene>"`) used by every composition/render tool: `{ scene, name, path, config, files, structureWarnings? }`. A duration over ~90 seconds adds `structureWarnings`: long videos should be MANY short scenes stitched by `build_film`, not one giant composition — heed it before authoring. Errors: `film_not_found`, `scene_already_exists`, `invalid_config`, `invalid_id`, `prereqs_missing`. |
| `get_scene` | `scene` | `{ scene, name, path, config, files }` — `config` is the validated scene config, `files` is `{ path, size }` for every file under the scene folder (`out/`, `node_modules/` and dotfiles excluded). Errors: `scene_not_found`, `invalid_id`. |
| `remove_scene` | `scene`, `deleteFiles?` = false | Removes the scene from its film's play order. `deleteFiles=true` also deletes the scene folder (composition, assets, rendered output) — irreversible, confirm with the user first. Without it the folder stays on disk and `list_films`'/`get_film`'s scene listing shows it as `unlisted`, so nothing silently disappears. Returns `{ id, path, removed, filesDeleted }`. Errors: `scene_not_found`, `invalid_id`. |
| `update_scene_config` | `scene`, `patch` (object: `name?`, `fps?`, `width?`, `height?`, `durationInFrames?`, `audio?` (array), `output?` (object)) | Patches scene settings — note the fields to change go inside `patch`, e.g. `{ scene: "film/scene", patch: { durationInFrames: 300 } }`. `output.format` selects the deliverable: `mp4` (default), `webm`, `gif`, `prores` (.mov), or `png-sequence` (a folder of frames). `output.transparent=true` keeps the alpha channel (webm/prores/png-sequence only; give the composition a transparent background). The output filename's extension follows the format automatically. `output.audioLimiter` (default `true`) brick-walls the mixed audio at −1 dBFS; set `false` only if you want the summed mix passed through untouched (track gains then sum directly — `amix` runs with `normalize=0`). Audio tracks take clip-relative `trimEndInFrames` (keep only the clip's first N frames) / `fadeInFrames` (fade up from the clip start) / `fadeOutFrames` (fade to silence ending at `trimEndInFrames` if set, else at the composition end) and `duck: true` (sidechain-compress this track under the mix of all non-ducked tracks — the bed dips while narration speaks and recovers in the gaps; needs both a ducked and a non-ducked track present). `scene.json` cannot be written via `write_composition_file`; this tool is the only way to change it, so config invariants are validated. **Diverging `fps`/`width`/`height` from the film's other scenes breaks the lossless concat** — `get_film`'s plan reports the mismatch. Returns `{ config, structureWarnings? }` (warnings only when this call is what made the scene long). Errors: `scene_not_found`, `invalid_config` (with the failing field), `invalid_id`. |

### Composition files and assets

Composition source files are always scene-scoped (`scene`, `"<film>/<scene>"`). Binary assets take a `target`, which is either a scene (composition-local assets) or a bare film id (master audio / overlay files that live in the film's own `assets/` and attach to its master timeline).

| tool | arguments | returns / notes |
|---|---|---|
| `read_composition_file` | `scene`, `path` | `{ path, content }`. Errors: `scene_not_found`, `file_not_found`, `path_not_allowed`, `invalid_id`. |
| `write_composition_file` | `scene`, `path`, `content` | Atomic write (temp + rename) into the scene folder. `.js`/`.mjs` content is syntax-checked first and rejected with `syntax_error` (line/column in `detail`) **before touching disk** — the previous file version survives a rejected write; `.json` is likewise parsed and rejected on bad JSON. Allowed extensions: `.html .htm .css .js .mjs .json .svg .txt .md`; `scene.json` is deny-listed (use `update_scene_config`). **Determinism lint:** JS/CSS is scanned for frame-driven contract violations and any hits come back as `warnings: [{ rule, line, snippet, message }]` on the write response `{ path, bytes, warnings? }` — these are **advisory, the file is written regardless**, but treat them as real unless the usage is known-safe. Comments and string literals are excluded from the scan. Rules: `date-now`, `performance-now`, `new-date`, `set-timeout`, `set-interval`, `request-animation-frame`, `math-random`, `three-clock`, `babylon-render-loop`, `babylon-begin-animation`, `css-transition`, `css-animation`, `canvas-save-restore` (a named function calling `ctx.save()` more often than `ctx.restore()` — the leftover transform/clip/style silently moves or hides everything drawn later in the frame), `classlist-mutation` (`classList.add`/`remove` accumulates DOM state across frames — hide scene containers by default in CSS; `classList.toggle(name, bool)` is exempt) and `sequence-gap` (literal `Sequence(start, duration)` calls statically checked against the scene duration: coverage holes and uncovered tails are named with frame ranges; dynamic args and single sequences are left alone). Errors: `scene_not_found`, `syntax_error`, `path_not_allowed`, `invalid_id`. |
| `sync_shared_files` | `sourceScene`, `targetScenes` (array, min 1), `files` (array of scene-relative paths, min 1) | Copies the named files from `sourceScene` into every scene in `targetScenes`, overwriting them. The maintenance half of the recommended multi-scene film pattern (every scene ships the SAME `composition.js` and differs only in a small `scene.js`) — each scene owns its own copy, so without this a one-line engine fix means rewriting it once per scene. Each target gets the same syntax check + determinism lint as `write_composition_file` (warnings come back per target), and **all** source files are read before anything is written, so a bad path fails before it half-updates the film. The source is skipped if it appears in `targetScenes`; `scene.json` remains deny-listed. Does **not** invalidate rendered output — re-render the affected scenes. Returns `{ sourceScene, files, scenesUpdated, results: [{ scene, written }] }`. Errors: `scene_not_found`, `invalid_config` (empty list), `syntax_error`, `invalid_id`. |
| `write_asset_file` | `target`, `path` (under `assets/`), `contentBase64` | Writes a binary asset (image/audio/font/video) from base64 into the target's `assets/`. Extension allow-list: `png jpg jpeg gif webp svg mp3 wav ogg m4a flac woff woff2 ttf otf json txt mp4 webm mov`; 25 MB decoded cap → `asset_too_large` (put larger files in the workspace library instead and pull them in with `use_shared_asset`). Reference from the composition/timeline as `assets/<name>`. Errors: `scene_not_found`/`film_not_found`, `asset_too_large`, `path_not_allowed`, `invalid_id`. |
| `probe_asset` | `path`, `target?` | Reads one media file's technical properties with **ffprobe**: `{ container, durationSeconds, bitRate, streams, video: {codec,width,height,fps,frames,pixFmt,durationSeconds}\|null, audio: {codec,channels,sampleRate,durationSeconds}\|null, hasAudio, notes? }`. With `target` (`"<film>"` or `"<film>/<scene>"`) the `path` is `assets/`-relative; **omit `target`** to probe a workspace-library file by its library-relative path. `list_assets` only reports bytes/mtime/kind — this is how you learn how LONG a clip is, what size it is, and whether it carries audio, before building a scene around it. `notes` flags properties that bite at render time, most importantly that **H.264/HEVC cannot be decoded by the render browser** (a `<video>` using such a file fails even though the page's own `canPlayType()` says otherwise — transcode to VP9/WebM first). Returns `probed: false` rather than an error when ffprobe is unavailable or the file is not media. Errors: `file_not_found`, `path_not_allowed`, `invalid_id`. |
| `list_assets` | `target` | `{ files: [{ path, bytes, mtime, kind, audioRefs }] }` for everything under the target's `assets/`. `kind` is `image`/`audio`/`font`/`video`/`data`; `audioRefs` is how many audio tracks reference the file (the scene's `config.audio`, or the film's master timeline, depending on what you targeted) — use this to tell a load-bearing asset from an orphaned take before cleaning up. |
| `delete_asset` | `target`, `path` (under `assets/`), `updateAudio?` = false | Deletes one file. Returns `{ path, deleted, audioRefs, audioTracksRemoved, audio? }`. **`audioRefs` is always reported**, so you're never unaware that you just orphaned an audio track — a dangling `src` doesn't fail at delete time, it fails much later as an ffmpeg mux error. Pass `updateAudio: true` to drop those tracks in the same call (the updated `audio` track list comes back). Irreversible. Folders are not deleted. Errors: `file_not_found`, `path_not_allowed`, `invalid_config` (path is a folder), `invalid_id`. |
| `rename_asset` | `target`, `from`, `to` (both under `assets/`), `updateAudio?` = false | Moves/renames within the target's `assets/`. Returns `{ from, to, audioRefs, audioTracksUpdated, audio? }`. An existing destination is **refused, not overwritten** (`invalid_config`). With `updateAudio: true` the referencing tracks are repointed at the new path, preserving each track's `startInFrames`/`gainDb` (the updated `audio` track list comes back). Errors: `file_not_found`, `path_not_allowed`, `invalid_config`, `invalid_id`. |

### Shared asset library

New in v0.20: a per-workspace library of files the human places for agents to use — the answer to "the user says they already gave me the footage/audio."

| tool | arguments | returns / notes |
|---|---|---|
| `list_shared_assets` | — | Enumerates the workspace LIBRARY — large media the human dropped in via the Studio's upload panel or directly on disk at `<workspace>/library`. Returns `{ workspace, files: [{ path, bytes, mtime, kind }] }`. Read-only from this surface. If the user mentions having provided a file, look here first. |
| `use_shared_asset` | `target`, `path` (library-relative, from `list_shared_assets`), `as?` (destination under the target's `assets/`, default `assets/library/<path>`) | Pulls a library file into a scene's or film's `assets/` so it can be referenced from compositions and audio timelines like any other asset. Hardlinked when the filesystem allows — a 500 MB plate costs no extra disk — copied otherwise; either way the scene/film stays self-contained and renders hermetically. Pulling the same file again refreshes the link/copy, so an updated library file propagates on request. Returns `{ from, path, bytes, linked }`. Errors: `file_not_found` (library path doesn't exist), `invalid_id`. |

### Audio / narration (v0.6; six vendors since v0.20)

Narration comes from a **speech vendor**: `system` (the Windows speech exe at `MOTION_STUDIO_TTS_EXE`), `azure` (Azure AI Speech, needing `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION` in the environment), `piper` (local neural voices — needs Piper installed via `pip install piper-tts` plus downloaded `.onnx` voices; offline, free, any OS), `elevenlabs` (ElevenLabs cloud voices — best quality; needs `ELEVENLABS_API_KEY`; free tier with attribution), `openai` (OpenAI `gpt-4o-mini-tts` — style-instructable; needs `OPENAI_API_KEY`; no free tier), or `deepgram` (Deepgram Aura-2 — best free cloud tier, $200 signup credit; needs `DEEPGRAM_API_KEY`). Omit `vendor` and the machine's configured default is used — `list_vendors` says which that is and why. The user may configure an ordered **preference chain** rather than one vendor, in which case a vendor-less call uses the highest-ranked one that is available and the result carries `vendorChain` + a `vendorNote` naming anything skipped; **a vendor you name explicitly is never redirected** — it runs or it fails. An unconfigured vendor returns `tts_unavailable`, which is a **setup problem for the user**, not something to retry. See [tts-setup.md](tts-setup.md). Synthesized narration is a normal audio track — mixed into the final render/build by FFmpeg (mp4/webm/prores carry audio; gif/png-sequence do not). `capture_preview_frame` is always silent.

| tool | arguments | returns / notes |
|---|---|---|
| `list_vendors` | `capability?` (`speech` \| `music`), `probe?` = true | `{ speech: {…}, music: {…} }`, each `{ active, activeSource, chain, preferred, fellBack, allVendors, vendors: [{ id, label, active, priority, available, requires, offline, error?, voiceCount? }] }` — which vendor each generator uses by default, whether each is usable right now, and what to configure if not. **`chain`** is the user's ordered preference (usually one entry); **`preferred`** is its head, **`active`** is the vendor that will ACTUALLY run (first in the chain that is available), and **`fellBack: true`** when those differ. Each vendor's **`priority`** is its 1-based rank in the chain, or null if outside it. `probe: false` reports configuration only (no exe spawn, no network) and then `active` is just the head. The speech settings carry `favoriteVoices` (vendor → starred voice names) and the music settings `favoritePrograms` — voices/instruments the user starred in the Studio; prefer them when a request doesn't name one. Never reports a credential, only its source. |
| `list_voices` | `vendor?`, `locale?`, `search?`, `limit?` = 50, `offset?` = 0 | `{ vendor, total, returned, truncated, voices }`. The `system` vendor returns plain names; `azure` returns `{ name, locale, gender, styles? }` — filter with `locale` (e.g. `"en-US"`) or `search`, since the Azure catalogue is several hundred voices; `piper` returns the downloaded voice files (`en_US-lessac-medium`); `elevenlabs` returns the account's voice library (pass the `name` — a `voice_id` — back, or a display name that is unique); `openai` and `deepgram` have fixed catalogues (`marin`…, `aura-2-thalia-en`…). Error: `tts_unavailable`. |
| `synthesize_speech` | `target`, `text` (req), `vendor?` (`system`\|`azure`\|`piper`\|`elevenlabs`\|`openai`\|`deepgram`), `voice?`, `rate?` (−10..10), `volume?` (0..100), `style?` (azure/openai), `mode?` = `attach`, `assetPath?` (under `assets/`, default `assets/narration-<n>.wav`), `startInFrames?`, `gainDb?`, `sentenceTimings?` = false, `sentenceGapSeconds?` = 0.3, `deterministic?` (piper/elevenlabs) | Target a SCENE for scene-local narration, or a FILM (`"<film>"`) to write master-timeline narration into the film's `assets/`, placed by absolute film frame — the normal choice for long-form. Speaks `text` to a WAV and returns `{ target, assetPath, vendor, vendorSource, durationSeconds, durationInFrames, fps, voice, sampleRate, peakDb, meanDb, warnings?, … }` — use `durationInFrames` to size the `Sequence()` (or film placement) the narration plays under, and **`peakDb`/`meanDb`** to balance a music bed against the narration without rendering first. The user may have STARRED favorite voices in the Studio: check `favoriteVoices` (vendor → voice names) in `list_vendors`' speech settings and prefer one when the request doesn't name a voice. `sentenceTimings: true` synthesizes per sentence, joins the clips with `sentenceGapSeconds` of silence (replacing — not stacking on — the vendor's own inter-sentence pad), and adds `timings: [{ text, startSeconds, startInFrames, durationSeconds, durationInFrames }]` — exact caption/cue placement. `deterministic: true` pins the output so identical input yields identical timing across runs — Piper via `--noise-scale 0 --noise-w 0`, ElevenLabs via a fixed seed; the other vendors report it in `warnings`. `elevenlabs` accepts a `voice_id` or unique display name; `openai`/`deepgram` chunk text past their per-request caps (4,096 / 2,000 chars) at sentence seams and report `chunked: N`. An explicit `vendor` differing from the machine default adds a `vendorNote`. `mode:"attach"` also appends the clip to the target's audio tracks (scene `config.audio`, or the film's master timeline) so the next render/build mixes it in; `mode:"asset-only"` only writes + reports (wire it in later with `update_scene_config`/`update_film`). An option the chosen vendor doesn't support (e.g. `style` on `system`) is reported in `warnings`, not silently dropped. Errors: `tts_unavailable`, `unsupported_voice`, `tts_failed`, `path_not_allowed`, `invalid_id`. |

### 3D libraries (v0.7, optional)

Attach a heavier rendering library to a scene. The build is copied **locally**
into the scene (never a CDN at render time, so renders stay hermetic). Builds
are **committed** under `engine/vendor/libs/`, so this works on a fresh clone with
no setup step; `node scripts/fetch-libs.mjs` is for upgrading or repairing them.
A missing build returns `library_unavailable`.

| tool | arguments | returns / notes |
|---|---|---|
| `add_library` | `scene`, `library` ∈ `three` \| `babylon`, `scaffold?` = true, `addons?` (three: `geometries` \| `loaders` \| `postprocessing`; babylon: `loaders`) | Vendors the library (+ any addons) into the scene and (when `scaffold`) replaces `composition.html/js/css` with a frame-driven starter; records `config.libraries`. Returns `{ library, version, global, addons, copied, scaffolded, notes }`. **`three`** = Three.js (~600 KB); **`babylon`** = Babylon.js (~8 MB, built-in glow/bloom/postprocessing). Three addons: `geometries` = `THREE.TeapotGeometry`; `loaders` = `THREE.GLTFLoader`; `postprocessing` = EffectComposer/RenderPass/UnrealBloomPass/ShaderPass + shader deps, injected in load order (multi-file addons supported). Babylon addon `loaders` adds glTF/GLB import via `SceneLoader`. **Provenance:** records `config.libraryBuilds` = `{ version, sha256, bytes }` per copied file, and returns each `copied` entry with its `sha256`. The builds are committed and version-pinned, with `engine/vendor.lock.json` recording which upstream build each came from, so a render can be traced to exact bytes — see [3d-libraries.md](3d-libraries.md) §3.5. Errors: `scene_not_found`, `library_unavailable`, `invalid_config`, `invalid_id`. |

The returned `notes` are **determinism rules you must follow** in the composition:
drive all animation from the injected `frame` — no `requestAnimationFrame`, no
`THREE.Clock` / Babylon `runRenderLoop` / particle systems (all wall-clock based).
The starters set `preserveDrawingBuffer` + a per-frame GL `finish()`, and compile
shaders up front (else a single-frame capture is blank). **Loading a glTF/GLB
model** additionally needs `MOTION_STUDIO_ALLOW_LOCAL_FETCH=1` (file:// fetch) and
a working recipe — see [3d-libraries.md](3d-libraries.md).

### Music (v0.8; two vendors since v0.17)

Compose a music bed from a note spec **you author**. The spec becomes MIDI and is
rendered against a General MIDI SoundFont, and — like `synthesize_speech` — the
result is a normal audio track mixed into the final render/build. Two vendors:
`node` (default — renders in-process, works on any OS, needs only a SoundFont)
and `fluidsynth` (the Windows exe chain: `MOTION_STUDIO_MIDI_EXE` +
`MOTION_STUDIO_FLUIDSYNTH` + `MOTION_STUDIO_SOUNDFONT`). Omit `vendor` to use the
configured default — `list_vendors` says which that is. A vendor that is not
usable → `music_unavailable`, naming what to fix (and any sibling that is ready).
See [music-setup.md](music-setup.md).

| tool | arguments | returns / notes |
|---|---|---|
| `synthesize_sfx` | `target`, `spec` (req: `cues[]`, optional `durationInFrames`/`sampleRate`/`normalize`/`ceilingDb`), `mode?` = `attach`, `assetPath?` (default `assets/sfx-<n>.wav`), `startInFrames?`, `gainDb?` | Target a SCENE, or a FILM to lay the cue bed over the whole film's master timeline — "a chime on every scene cut" is a plain map over the scene `filmOffset`s from `get_film`'s plan. Renders a list of sound-effect **cues** into one mono WAV and (in `attach` mode) appends the track. **Pure JS — nothing to install, works on every OS, and has no `*_unavailable` error**, unlike speech and music. One call makes the whole bed: a single track holding every cue at its absolute time. **Time is in frames**: `atFrame` matches `startInFrames`/`filmOffset`; `at` (seconds) is accepted instead — exactly one of the two. `gain` is the cue's **peak amplitude 0..1, not dB**. Types: `chime`, `whoosh`, `shimmer`, `thud`, `tone`; pitched cues take `pitch` (MIDI) **or** `hz`. Levels: `normalize:"ceiling"` (default) attenuates only a mix hotter than `ceilingDb`, so the returned `peakDb` is the real level — also reports `rawPeakDb` and `appliedGainDb`. `fps` and the default bed length come from the target (the scene's duration, or the whole film's length). Limits: 512 cues, 30 s per cue, `sampleRate` ∈ 22050/44100/48000 (a 10-minute 44.1k bed is ~53 MB — prefer 22050 for long beds). A cue overhanging the end is clamped and counted in `clamped`; one starting past the end is an error. Errors: `invalid_sfx_spec` (offending cue index in `detail`), `path_not_allowed`, `invalid_id`. See [sfx-setup.md](sfx-setup.md). |
| `synthesize_music` | `target`, `spec` (req — note form `{ bpm, tracks }`, or compiled form `{ progression, … }`), `vendor?` (`node` \| `fluidsynth`), `mode?` = `attach`, `assetPath?` (under `assets/`, default `assets/music-<n>.wav`), `startInFrames?`, `gainDb?`, `duck?` | Target a SCENE for scene-local music, or a FILM (`"<film>"`) to write the score into the film's master timeline — the normal choice for long-form (tile a short theme across the film at stepped `startInFrames`). Renders `spec` to a WAV and returns `{ target, assetPath, bpm, tracks, notes, musicalDurationSeconds, durationSeconds, durationInFrames, fps, bytes, … }`. `durationInFrames`/`durationSeconds` come from the WAV (includes FluidSynth's reverb tail — longer than `musicalDurationSeconds`); use it to size the video, and `startInFrames`/`gainDb` (e.g. `-8`) to place and balance the bed under narration. `mode:"attach"` also appends the track (`duck: true` marks it for sidechain auto-ducking under the non-ducked tracks); `mode:"asset-only"` writes + reports only. Also reports the `vendor` used and the **measured `peakDb`** of what was written (plus `attenuatedDb` when `music.targetPeakDb` pulled it down) — you cannot hear the bed, so that number is how you know whether it will fight the narration; an explicit `vendor` differing from the machine default adds a `vendorNote`. Spec: `bpm`, plus `tracks` of notes — `program` = General MIDI instrument `0..127` (0 piano, 24 nylon guitar, 32 acoustic bass, 40 violin, 48 strings, 56 trumpet, 73 flute…), `drums:true` routes the track to GM percussion, each note is `{ pitch 0..127 (60=middle C), start & duration in beats, velocity? 1..127 }`. The user may have STARRED favorite instruments in the Studio: check `favoritePrograms` in `list_vendors`' music settings and prefer those when the brief doesn't name instruments. OR skip note-writing: pass a chord progression + style and the server compiles the notes — e.g. `spec: { bpm: 96, progression: ['D','A','Bm','G'], style: 'pad-ballad', bars: 8 }`. Chords are letters (`C`, `F#m`, `Bb7`, `Dmaj7`, `Esus4`, `C/E`) or roman numerals (`I`, `vi`, `V7`, `bVII`) with `key`; styles: `pad`, `pad-ballad`, `arp`, `drive`, `lullaby`. Optional `bars` (progression cycles one chord per bar; +1 held closing bar), `beatsPerBar` (4), `layers` (subset of the style's named layers), `seed` (deterministic variation). The compiled take is voice-led with mix headroom built in, and the response adds `compiled: {style, bars, chords, notes}`. Exactly one of `tracks` \| `progression`. Errors: `music_unavailable`, `invalid_music_spec` (`detail.problems` lists every bad field, and names an unknown chord/style/layer), `music_failed`, `path_not_allowed`, `invalid_id`. See [music-setup.md §Composing without writing notes](music-setup.md#composing-without-writing-notes-v020). |

### Building a film

| tool | arguments | returns / notes |
|---|---|---|
| `build_film` | `film` (req), `plan?` (bool), `outputFilename?` (override + persist), `audioTargetPeakDb?` (override + persist, −60..0 or `null`), `burnCaptions?` (override + persist) | Assembles the film's already-rendered scenes into its deliverable, as an **ASYNC JOB** — returns a `jobId` immediately; block with `wait_for_render` (or poll `get_render_status`). The build concatenates scene outputs **losslessly** (`ffmpeg -c copy`, no re-encode, near-instant), lays the film's master audio timeline over the whole length (replacing per-scene audio when present), and — only when the film has overlays or burns captions — runs ONE finishing encode that composites them (crf/preset taken from the first scene's output config). Captions always also write a `.srt` sidecar. Output lands in the film's `out/`. Every scene must already be rendered (`scene_not_rendered` lists offenders) **and still match the settings it was rendered at** (`stale_render` — change a scene's duration/size/fps/format after rendering and its file is no longer the scene; see the render sidecar in docs/film-setup.md); scenes must share resolution/fps/format (`inconsistent_scenes` — only mp4/webm/prores concatenate losslessly). The finished job's status carries the measured `audio` block (`peakDb`/`meanDb`/`clipping`) when a master timeline exists — **read it**; a bad mix is the one defect you cannot see. Set `audioTargetPeakDb` (e.g. `-2`) to have the film measured and re-muxed once to that level instead of guessing gains. Pass `plan: true` to get `{ film, plan: true, totalFrames, durationSeconds, fps, format, sceneLayout, problems }` WITHOUT building (each `sceneLayout` entry carries `rendered` plus **`renderVerified`** — `true` matches the config, `false` means stale with a `staleRender` breakdown, `null` means rendered before the sidecar existed) — works before the scenes are rendered, which is exactly when you need each `filmOffset` to place narration and cues; nothing is assembled or written. Iterating? Re-render only the scene you changed, then `build_film` again — other scenes' outputs are reused. Non-plan calls return `{ jobId, state, queuePosition?, outputPath, totalFrames, filmId, hint }`. Errors: `scene_not_rendered`, `stale_render`, `inconsistent_scenes`, `invalid_film`, `file_not_found` (missing master-audio/overlay asset), `path_not_allowed`, `film_not_found`, `invalid_id`, `prereqs_missing`. |

Note there is **no separate "saved film" concept anymore** — the film document `build_film` reads is the same one `create_film`/`update_film`/`get_film` edit, and the same one the Studio's film editor shows. The concat step is always `-c copy` (lossless): the scenes' own `output.crf`/format is what ships, so choose the deliverable quality when you render each scene. A finishing re-encode happens exactly once, and only when the film has overlays or burns captions.

### Preview

| tool | arguments | returns / notes |
|---|---|---|
| `capture_preview_frame` | `scene`, `frame` = 0 | Renders exactly one frame through the real render path (Puppeteer Chromium — identical pixels to the final render) and returns it as an MCP **image** content block (PNG). Errors: `scene_not_found`, `invalid_config` (frame out of range), `composition_error`, `frame_timeout`, `browser_launch_failed`, `invalid_id`. |
| `capture_preview_frames` | `scene`, `frames?` (array), `count?` = 5 | Same render path, but **N frames from one page load** — returns an image block per frame, in the order requested, followed by a text block listing them. Pass explicit `frames`, or `count` for evenly-spaced frames spanning the composition (first and last always included). Max 24 per call → `invalid_config`. **Prefer this whenever you want more than one frame:** a single capture pays a full Chromium launch, page load, and re-run of the composition's one-time setup, so five separate captures pay that five times. |
| `render_still` | `scene`, `frame`, `outputFilename?` = `still-<frame>.png` | Same single-frame render, but written to a `.png` inside the scene's `out/` dir — for poster frames and thumbnails. Returns `{ outputPath, bytes, frame }`. |
| `preview_audio` | `target`, `outputFilename?` = `audio-preview.wav` | Target a SCENE (mixes `config.audio` at the scene length) or a FILM (mixes the film's master audio timeline at the full film length — audition the whole soundtrack before building). Mixes to a standalone WAV in the target's `out/` using the **exact** filter graph the final render/build will use (delay, gain, trim/fades, ducking, limiter) — no video pass, so it takes seconds. Returns `{ target, kind, outputPath, durationSeconds, limiter, balanceWarnings, tracks: [{ …track, clipPeakDb, clipMeanDb, clipDurationSec? }], mix: { peakDb, meanDb, clipping, envelopeDb, silentTailSeconds } }`. `balanceWarnings` names any track whose effective level (`clipMeanDb + gainDb`) sits ≥8 dB under a louder overlapping track — likely inaudible even though nothing clips; fix the gains before rendering (`duck: true` tracks are exempt background). `envelopeDb` is the mix's per-second RMS (`null` = digital silence) and `silentTailSeconds` the length of the dead run at the end, so a mix that goes silent early is visible even when the whole-file peak/mean look healthy. Errors: `no_audio_tracks` (empty timeline), `invalid_film` (film has no scenes yet, so no length to mix against), `path_not_allowed`, `ffmpeg_failed`, `invalid_id`. |

### Rendering

| tool | arguments | returns / notes |
|---|---|---|
| `render` | `scene`, `frameRange?` = `[start, end]` inclusive, `workers?` (default: the user's global **default workers** setting; omit unless you have a reason), `outputFilename?`, `preflight?` = true, `proxy?` = `{ scale?, frameStep? }` | Starts an async job for the scene's configured output format; returns `{ jobId, state, queuePosition?, outputPath, totalFrames, workers, proxy? }` immediately. One render runs at a time; further submissions **queue FIFO**, up to 10 deep, and start automatically. A full queue fails with `queue_full`. `workers` > 1 splits capture across parallel Chromium processes. **Pre-flight:** evenly-spaced frames (both endpoints included) are probed before the render commits, so a composition that only breaks at frame 90 fails in seconds instead of after 90 frames and N spawned workers. Failures keep their real code (`composition_error` / `frame_timeout`) with `detail.phase = "preflight"`. Skipped under 30 frames; pass `preflight: false` to disable. **Frame-count verification:** when the encode finishes, the file's actual frame count is checked against what was rendered; a mismatch fails with `short_render` rather than returning a truncated file, and the result carries `framesVerified` (false only when ffprobe is unavailable). **Render lock:** the scene is locked for the duration, so a *second process* rendering the same scene fails fast with `render_already_in_progress` instead of silently interleaving frame writes. In-process submissions still queue as before. **Proxy/motion preview:** `proxy: { scale?, frameStep? }` renders a cheap draft for checking motion in ~1/8 the time — capture at `width×scale` (0.1–1, default 0.5; dims floored to even for the encoders), every `frameStep`-th frame (default 2), encoded at the rational rate `fps/frameStep` so wall-clock duration is preserved. Serial only (`workers` is ignored), pre-flight and the audio mux are skipped, and the output gets `.proxy` before the extension (`output.proxy.mp4`) so a draft can never overwrite the deliverable. Bad values fail with `invalid_config` naming the offending field. Do NOT set mp4 `crf` to 0 for "maximum quality": CRF 0 is lossless H.264 (Hi444PP profile), which most players show as BLACK video with working audio — `crf 18` is the visually-lossless choice that plays everywhere; such a render still succeeds but carries `encodingWarnings` in the job status. |
| `get_render_status` | `jobId` | `{ state: queued\|running\|done\|error\|cancelled, framesDone, totalFrames, percent, renderFps, etaMs, queuePosition?, outputPath?, error? }`. Poll until terminal — or use `wait_for_render` instead of a polling loop. When the render/build carried audio, adds `audio: { tracks, limiter, peakDb, meanDb, clipping, balanceWarnings }` — the measured level of the final mix, plus warnings for any track buried ≥8 dB under a louder overlapping one (likely inaudible; also logged as `[warn]` in `get_logs`). `encodingWarnings` lists player-compatibility advisories — currently mp4 + `crf: 0`, whose lossless Hi444PP profile most players show as black video; relay these to the user. Proxy jobs carry `proxy: { scale, frameStep }` so a draft is never mistaken for the deliverable. Error: `job_not_found`. |
| `wait_for_render` | `jobIds` = `[…]` (1–16), `timeoutMs?` = 30000 (1,000–50,000 ms) | Blocks until **every** listed job is terminal, or the timeout elapses. Returns `{ timedOut, jobs }` — each `jobs[]` entry has the `get_render_status` shape, including the structured `error` for failed jobs and the measured `audio` block for finished ones. Check states individually: one failed scene does not stop the others. Waiting on queued jobs is fine (FIFO). The ceiling is deliberately below the typical 60s MCP client request timeout — a timeout here is **not** an error, the jobs keep running; call again to keep watching. Job ids live in server memory only — if the server restarts they're gone (`job_not_found`), so verify finished work by its output file, not by id. Error: `job_not_found` if any id is unknown. |
| `cancel_render` | `jobId` | Aborts a running job and kills every child process (Chromium workers, FFmpeg); dequeues a queued job without starting it. Idempotent on finished jobs. |
| `list_render_jobs` | — | All jobs this session, newest first, with status snapshots. |
| `get_logs` | `jobId`, `tail?` = 100 | The job's log lines (engine phases, warnings, FFmpeg stderr on failure) — read this before diagnosing a failed render or build. |

## Typical agent session

The recommended shape for anything longer than a single shot: one film, one scene per beat, master audio placed on the film rather than per scene.

```
create_film { name: "Product Launch", fps: 30, width: 1920, height: 1080 }
                                                 → { film: "product-launch", sceneDefaults: {...}, next: … }

create_scene { film: "product-launch", name: "Intro", durationInFrames: 150 }
                                                 → { scene: "product-launch/intro", config, files }
create_scene { film: "product-launch", name: "Feature Tour", durationInFrames: 240 }
                                                 → { scene: "product-launch/feature-tour", … }
create_scene { film: "product-launch", name: "Outro", durationInFrames: 120 }
                                                 → { scene: "product-launch/outro", … }

(read resource motion-studio://reference/frame-api)
write_composition_file { scene: "product-launch/intro", path: "composition.js", content: … }
                                                 → syntax_error → fix → ok; warnings? fix determinism hits
capture_preview_frames { scene: "product-launch/intro", count: 5 }
                                                 → inspect 5 images from ONE page load
(… author + preview feature-tour and outro the same way …)

render { scene: "product-launch/intro" }        → jobId1
render { scene: "product-launch/feature-tour" } → jobId2 (queues behind jobId1)
render { scene: "product-launch/outro" }        → jobId3 (queues)
wait_for_render { jobIds: [jobId1, jobId2, jobId3] }
                                                 → blocks → all done

build_film { film: "product-launch", plan: true }
                                                 → sceneLayout: each scene's filmOffset — read this BEFORE
                                                   placing narration, so cues land exactly on the cut

synthesize_speech { target: "product-launch", text: "…", sentenceTimings: true }
                                                 → narration attached to the film's master timeline at frame 0
synthesize_music { target: "product-launch",
                    spec: { bpm: 96, progression: ["D","A","Bm","G"], style: "pad-ballad" },
                    gainDb: -10, duck: true }
                                                 → theme tiled across the film, ducked under narration
preview_audio { target: "product-launch" }      → audition the whole soundtrack; check balanceWarnings

build_film { film: "product-launch", audioTargetPeakDb: -2 }
                                                 → jobId4 (async)
wait_for_render { jobIds: [jobId4] }            → done, outputPath,
                                                   audio: { peakDb, clipping, balanceWarnings }
```

For a one-shot video, the same tools collapse to a single scene: `create_film` → one `create_scene` → author/preview/render that scene → `build_film` (no master audio needed unless you want narration/music, in which case `synthesize_*` still targets the film).

To deliver a transparent overlay instead of an mp4:
`update_scene_config { scene: "<film>/<scene>", patch: { output: { format: "webm", transparent: true } } }`,
give the composition a transparent background, and render — the output drops
onto any timeline as an alpha overlay.

The updated agent skill in [SKILL.md](SKILL.md) encodes this workflow, the authoring contract, and error handling for direct use as a Claude skill (pair it with `frame-api.md` as `references/frame-api.md`).
